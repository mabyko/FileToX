# SwiftUI 화면과 변환 흐름 설계

Filee에서 영감을 받아 Mac 전용 화면과 동작을 구현한다. 입력을 넣고 프리셋을 선택하는 도넛이 주된 변환 흐름이고, 홈은 드롭·작업 이력을 제공한다. 형식·프로필·프리셋·실행 가능 여부는 C# host가 결정한다. 기존 두 형식 타일과 단순 변환 창을 이 흐름으로 교체했다. 홈·도넛·프리셋·프로필·일반·테마·엔진 설정을 연결했고, 자동 변환 폴더와 앱 내 엔진 다운로드는 아직 연결하지 않았다.

## 두 원형 메뉴와 홈 변환

- 기본 호출 키는 형식 변환 `⌃`, 파일 도구 `⌃⇧`다. 메뉴가 열린 후 키를 놓아도 유지되며, 같은 드래그에서 다른 호출 키를 눌러 전환한다. 두 메뉴의 호출 순서 설정은 최초 호출에 적용한다.
- 호출 키·추가 키·호출 순서는 두 메뉴에 각각 저장한다. 동일한 키 조합은 거절하고, 기존 primary 설정을 유지한다. 기존 primary가 `⌃⇧`이면 두 번째 기본값은 `⌃⌥⇧`로 피한다. 이 macOS 설정은 UserDefaults에 저장하며 host의 엄격한 설정 JSON에 넣지 않는다.
- 형식 변환은 기존 사용자 프로필을 유지한다. 파일 도구 자동 모드는 입력 종류에 맞는 도구 최대 9개와 Finder에서 보기·파일 복사·경로 복사를 제공한다. 사용자 모드에서는 저장된 모든 프리셋과 파일 작업을 최대 12개까지 순서대로 배치한다. 도구 메뉴 배치도 UserDefaults에 저장한다.
- host는 `tools` 및 `presetOptions`에서 실제 실행 가능 여부와 이유를 제공한다. UI는 미지원 도구를 실행 가능하다고 추정하지 않는다. 파일 작업은 존재하는 로컬 입력만 사용하며 원본을 변경하지 않는다. 파일 복사는 클립보드에 파일 URL을 기록한다.
- 홈에서 파일 선택·드롭은 홈 안에 입력과 출력 선택을 표시한다. 원형 메뉴는 별도 버튼으로 연다. 클릭 모드는 방향키·Enter·M(메뉴 전환)·Escape를 지원하며 드래그 모드는 Finder 포커스를 가져오지 않는다.
- 선행 HTML 시안 `filetox-ux-direction.html`은 예시 데이터로 만든 초기 방향이며, 실제 구현의 범위·동작은 이 문서와 앱 코드가 정의한다.

## 화면과 상태의 소유자

| 화면 | Swift가 소유할 상태 | host가 제공·저장할 내용 |
| --- | --- | --- |
| 사이드바·홈 | 선택한 페이지, 파일 드롭, 펼친 오류 목록 | 최근 작업 이력, 작업별 여러 결과, 실패 파일과 재시도에 쓸 프리셋 |
| 도넛 | 위치·크기, hover 섹터, 드롭/클릭 모드, 애니메이션 | 입력별 프로필·프리셋 순서, 실행 가능 여부와 이유, 작업 진행·결과 |
| 원형 툴바 | 프로필 편집 초안, 섹터 드래그 순서 | 최대 12개 섹터를 포함한 프로필, 확장자·혼합 선택 규칙 |
| 프리셋 | 선택·검색·편집 초안, 저장 오류 | 원본 Preset의 모든 옵션과 기본값, 복제·삭제·저장 결과 |
| 자동 변환 폴더 | 규칙 편집 초안, 실행 상태 표시 | 감시·파일 안정화·중복 처리·변환 큐와 규칙 |
| 일반·호출 키·테마·정보 | macOS 권한·로그인 항목·창·메뉴바 연동 | 원본 출력 기본값·이력 설정, 도넛 외형 등 제품 설정 |
| 변환 엔진 | 상태 표시·설치 또는 경로 선택 | 엔진 검사·우선순위·설치 가능 여부·설치 진행·변환 경로 |

Swift가 원본 `Preset` 전체를 덮어쓰는 부분 DTO를 만들지 않는다. host에서 받은 전체 초안에 편집한 필드만 반영하고 host가 검증·저장한다. 미지원 옵션은 값을 유지하고 읽기 전용으로 표시한다. 원본 camelCase 필드와 문자열 enum 값은 유지한다. 전체 JSON 초안의 null, 배열 순서, 편집하지 않은 필드도 보존한다. 버전이 다른 JSON은 host가 저장 전에 거절한다. 설정은 host 한 곳에서 저장하며 Swift의 UserDefaults에 같은 값을 중복 저장하지 않는다.

## 도넛 호출부터 결과까지

1. **Finder Option 드래그:** AppKit이 비활성 패널을 열고 실제 파일이 DragEnter로 들어올 때 URL을 읽는다. 실제 파일 URL이 없으면 투명한 드래그 수신 창만 대기하고 도넛은 보이지 않는다. 텍스트 드래그·범위 선택에는 화면을 열지 않는다.
2. **선택 판단:** FilesEntered에서 같은 파일 목록은 한 번만 resolve한다. 요청 번호로 최신 응답만 반영하고 응답 전에 드롭은 `.none`으로 거절한다. 응답의 섹터 수·순서를 그 호출 동안 고정하며, 늦은 엔진 갱신은 활성 여부와 이유만 바꾼다. 버튼 해제 후 250 ms 동안 드롭을 기다린다. 드롭 URL이 resolve한 목록과 다르면 다시 resolve하고 검증이 끝날 때까지 실행하지 않는다. job.start에서도 경로·프리셋을 다시 검증한다.
3. **형식 선택:** 프로필의 순서대로 부채꼴을 그린다. 첫 항목은 12시부터 시계 방향, 기본 반지름 150·중앙 구멍 비율 0.42다. 섹터에 드롭하면 `.copy`로 응답하고 원본을 이동하지 않는다.
4. **홈 드롭·파일 선택:** 파일을 알고 도넛을 열기 때문에 클릭 모드다. Finder 드래그와 같은 selection·convert 요청을 사용한다. 중심·Escape는 닫고 섹터 우클릭은 같은 프리셋 편집 화면을 연다.
5. **변환 진행:** 섹터를 접고 중심 진행 링으로 전환한다. 사용자가 링을 닫더라도 앱 상태가 작업을 계속 소유한다. 취소는 별도 작업 ID를 사용하고 완료 이벤트를 받을 때까지 취소 중으로 표시한다.
6. **긴 작업·완료:** 긴 작업은 진행 창으로 넘기고, 성공·실패와 결과 폴더 열기를 제공한다. 최근 변환은 파일별 행을 흩어 놓지 않고 한 배치당 카드로 저장한다. 부분 실패는 성공한 결과와 오류를 함께 표시하고 실패한 파일만 재시도한다. PDF·TIFF 병합 단계의 실패처럼 실패 파일 목록이 비어 있으면 원래 입력 전체와 당시 프리셋으로 재시도한다. 이력 저장을 꺼도 세션의 최근 작업에는 이 정보를 유지한다.

AppKit 패널은 변환 시작 직후 숨기는 현재 동작을 바꿔 진행 링을 유지한다. 패널과 작업의 수명을 분리해 다른 파일 드래그가 시작돼도 실행 중인 작업을 잃지 않는다. 앱 종료 시 활성 작업의 취소·완료 응답을 기다린다.

## 목록과 실제 실행 가능 여부

`Resources/FileeFormats.json`은 원본 전체 형식의 고정 스냅샷이다. 초기 표시·검색·출처 확인에만 사용한다. host 연결 후 실제 버전·형식·엔진 상태를 조회하고, 버전 불일치 시 스냅샷으로 변환 가능을 추측하지 않는다.

쓰기 가능 필드도 현재 변환 가능과 다르다. 예를 들어 HEIC는 원본의 읽기 전용 형식이고, 출력 가능한 DOCX도 입력·엔진에 따라 경로가 없을 수 있다. `folder`는 파일 확장자 없이 압축 해제 결과를 뜻하며, `*`는 프리셋의 같은 형식 변환을 뜻한다. 둘을 일반 파일 형식으로 만들어 표시하지 않는다.

`PresetAvailability`의 참고 위치는 `Filee.App/Services`다. helper에서는 Avalonia·EngineDownloadService 의존성 없이 프리셋 사용 가능 여부를 판단한다. 실제 변환 경로는 host의 `ConverterCatalog`·`RoutePlanner`가 판단한다.

혼합 입력 중 하나라도 변환 경로가 있으면 프리셋을 선택할 수 있다. 실행 가능한 파일 수와 처리 불가 입력을 함께 표시하고, 배치를 조용히 필터링하지 않는다. 합치기·압축 해제·PDF 병합·TIFF 병합은 일반 파일별 변환과 다른 검사와 결과 형태를 유지한다. 특히 `CombineIntoOne`은 알려지지 않은 확장자도 압축할 수 있으므로 무조건 거부하지 않는다.

## 편집과 접근성

홈·설정은 사이드바와 페이지로 구성하고 macOS 창 장식·글꼴·파일 선택기를 사용한다. 도넛은 하나의 렌더러를 실사용·프로필 편집 미리보기에서 공유한다. 실제 기능 없이 버튼만 활성화한 페이지는 만들지 않는다.

각 도넛 섹터는 프리셋 이름·동작·비활성 이유를 접근성 요소로 제공한다. 클릭 모드에는 키보드 선택과 Escape를 연결하고, 같은 프리셋을 선택할 수 있는 일반 목록도 제공한다. 도넛의 반지름·구멍 비율·불투명도는 `DonutSettings`로 설정한다. ThemeSettings.ReduceMotion이 null이면 macOS의 접근성 설정을 따르고, true이면 섹터 접힘·스프링 효과를 줄인다. 진행·결과를 색상이나 링 모양만으로 알리지 않는다.

## 구현 순서와 검증

첫 통합은 host 시작·catalog·selection·convert·cancel과 홈·도넛을 연결한다. 이미지 두 형식이 아니라 host가 제공하는 모든 실제 경로가 같은 흐름으로 실행되게 한다. 그 뒤 저장된 이력·실패 재시도, 전체 프리셋·프로필 편집, 설정·엔진 관리·폴더 감시를 연결한다.

검증은 도넛 좌표 판정, 최신 selection 응답, 클릭·드롭 공통 실행, 원본 Copy 응답, 여러 결과·부분 실패·취소·이력·재시도에 집중한다. 실제 Finder 포커스 유지와 여러 모니터·전체 화면·VoiceOver는 macOS 앱에서 확인한다.

참고 자료: `Filee.App/Views/MainWindow.axaml`, `Views/Pages/HomePage.axaml`, `ViewModels/RadialViewModel.cs`, `Controls/DonutMenu.cs`, `Controls/DonutMenu.Progress.cs`, `Services/RadialController.cs`, `Services/PresetAvailability.cs`, `ViewModels/Pages/ToolbarPageViewModel.cs`, `Views/PresetEditorView.axaml`, `Filee.Core/Profiles/ToolbarProfile.cs`, `Filee.Core/Presets/Preset.cs`, `Filee.Core/Settings/FileeJsonContext.cs`.

## 구현 검증 (2026-10-11)

실제 SwiftUI 앱의 도넛 JPG 클릭 → helper 변환 → 최근 이력을 확인했다. Finder 드래그를 받는 NSPanel에 `alpha=1/255` 배경을 둬 native hit-testing에서 빠지지 않도록 했다. 완전 투명한 `.clear` 배경에서는 DragEnter가 오지 않아 Finder가 자체 복사를 수행하는 문제가 재현됐다. 패널은 mouse-down 당시보다 새 drag pasteboard에 실제 로컬 파일 URL이 준비된 뒤 띄운다. 파일 드래그가 시작되기 전에 패널이 나타나 느린 움직임을 가로채거나, 이전 드래그의 URL을 사용하는 것을 막는다. 파일을 놓기 전에는 거의 투명한 패널만 있고, 입력별 selection을 받은 뒤 원형 메뉴를 표시한다.

전체 출력 형식은 사용자가 펼칠 때만 표시하고 접기 버튼도 같은 상태를 따른다. 설정 저장 후 엔진 상태를 새로 조회한다. 새 Finder 드래그는 selection을 다시 확인하고, 동일 파일의 수동 재열기는 이미 받은 selection으로 닫힌 도넛을 다시 표시한다. 초기 helper 연결 중 들어온 파일 열기는 연결 완료를 기다린다. 이력과 완료된 작업은 각각 최근 200개를 유지하고 실행 중인 작업은 보존한다. 실제 전체 포맷·기본 엔진·외부 엔진 표본과 제한은 [README](../../README.md)를 따른다.

## 두 메뉴 구현 검증 (2026-10-21)

- Debug 앱 빌드 및 Xcode 테스트 64개 통과: 두 단축키 저장·중복 거절·기존 키 보존, 드래그 중 메뉴 전환·취소·재시도, 프리셋/파일 작업 혼합 배치, 복사 작업의 원본 보존과 누락 파일 거절 등을 포함한다. 복사 검사는 테스트 전용 pasteboard를 사용했다.
- Swift Package 테스트 12개(실제 helper 통합 포함), helper `--selftest`, 기존 실제 엔진 smoke 22개 모두 통과했다. 스테이징 잔여 파일은 없었다.
- 별도 임시 데이터 폴더를 사용하는 네이티브 AppKit/SwiftUI 렌더에서 홈·두 호출 키 설정·두 원형 메뉴의 배치를 확인했다. 실제 `ConversionPanelController`의 키 이벤트로 M 메뉴 전환 → 방향키 → Enter를 보내 JPG 70% 변환 완료와 원본 보존을 확인했다.
